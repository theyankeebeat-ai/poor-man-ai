# Coding

Scope: Use this card to read a problem, name inputs and outputs, sketch pseudocode, estimate big-O, and check edge cases.

## Triggers

- coding
- algorithm

- complexity patterns

## Method

1. Read the problem until the asked result is clear.
2. Name the inputs and the outputs.
3. Sketch pseudocode before choosing syntax.
4. Estimate big-O as O(1), O(n), O(n log n), or O(n^2).
5. Check edge cases such as empty input, one item, and the boundary.
6. Use a stack trace only when one was actually provided.
7. Stop when the sketch matches the inputs, the output, and the cost.

## Formulas

- **constant** — `O(1)` — Work does not grow with input size, as with a direct lookup.
- **linear** — `O(n)` — One pass over n items, as with a single scan.
- **linearithmic** — `O(n log n)` — A typical efficient sort or balanced divide of n items.
- **quadratic** — `O(n^2)` — Nested passes over the same n items, which grows quickly.

## Checks

- Inputs and outputs are named.
- Pseudocode produces the asked result.
- The big-O label is O(1), O(n), O(n log n), or O(n^2), with a reason.
- Edge cases were checked, and no stack trace was invented.

## Limits

- This card teaches method.
- Editing a repository still follows the code tools.
- Do not invent a stack trace.
